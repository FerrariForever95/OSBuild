# Original source -> new native implementation

| Original (Nopnop `esp-idf-parallel-tft`) | New (`zeno_lcd`) | What changed |
|---|---|---|
| `components/tft_library/lcd_com.c` / `.h` -- `lcd_interface_cfg()`, `reg_lcd_write_data()`, `lcd_write_comm_byte()`, `lcd_write_data_byte()`, `lcd_write_addr()`, `lcd_write_color()`, `lcd_write_table()` | `lcd_bus.h` / `lcd_bus.c` | Per-pin `gpio_set_level()` calls replaced by one LUT lookup + one `GPIO_OUT_W1TS_REG`/`GPIO_OUT_W1TC_REG` write pair per byte (see `zl_lut_build()` in `zeno_pure.h`). WR strobe hold is now an explicit, tunable NOP count instead of relying on `-Og` call overhead. Solid-fill/blit transfers stream inside one CS/RS transaction instead of one `malloc()`'d column at a time. Added a FreeRTOS mutex (`zl_bus_lock()`/`unlock()`) since MicroPython can call in from more than one thread; the original had none because only its single `TFT` task ever touched the bus. |
| `components/tft_library/lcd_com.c` -- `touch_interface_cfg()`, `touch_gpio()`, `touch_avr_analog()`, `touch_getx()`, `touch_gety()`, `touch_getz()`, `touch_getxyz()`, `touch_getxy()` | `touch_drv.h` / `touch_drv.c` | Same electrode sequence, same trimmed-mean/dual-sample-compare acceptance, same constants. Pins are reconfigured once per axis (not per ADC sample) and the two ADC channels are configured once at `touch.init()`. The dead `z == 1023` 10-bit-era threshold is replaced with a configurable, default-disabled `z_max` gate. New: a debounce state machine (`zt_debounce_step()`) and `zl_touch_poll()`, which `touch.read()` uses; the original had no debouncing (its demo loop just polled `touch_getxy()` directly every iteration). |
| `components/tft_library/ili9488.c` / `.h` -- `ili9488_lcdInit()`, `ili9488_regValues[]` | `ili9488_panel.h` / `ili9488_panel.c` -- `zl_panel_init()`, `reset_off[]`/`reg_before_madctl[]`/`reg_after_madctl[]`/`wake_on[]` | Same command bytes and parameters, byte-for-byte, split around the one MADCTL (`0x36`) entry so rotation can be substituted. `exec_table()` replaces `lcd_write_table()`; same `TFTLCD_DELAY8` marker convention. |
| `components/tft_library/ili9341.c` -- `ili9341_lcdDrawPixel()`, `ili9341_lcdDrawMultiPixels()`, `ili9341_lcdDrawFillRect()`, `ili9341_lcdDisplayOn/Off()`, `ili9341_lcdInversionOn/Off()`, address-window (CASET/PASET/RAMWR) sequence | `ili9488_panel.c` -- `zl_set_window()`, `zl_fill_rect()`, `zl_draw_pixel()`, `zl_blit()`, `zl_panel_display()`, `zl_panel_invert()` | Same CASET/PASET/RAMWR byte sequence. `zl_draw_line()`/`zl_draw_rect()`/`zl_draw_circle()`/`zl_fill_circle()` are new (Bresenham/midpoint-circle on top of `zl_draw_pixel()`/`zl_fill_rect()`), added because the task brief's drawing-API list (pixel, filled rect, h/v lines) is a subset of what `lcd.*` exposes to Python; the extra shapes reuse the same primitives and add no new bus behavior. |
| `components/tft_library/lcd_lib.c` / `lcd_lib.h` -- higher-level line/rect helpers built on the `ili9341_*` primitives | Reimplemented directly in `ili9488_panel.c` (`zl_draw_line`, `zl_draw_rect`) | Same horizontal/vertical fast-path-via-fill-rect, diagonal-via-per-pixel approach; rewritten against `zl_fill_rect()`/`zl_draw_pixel()` rather than the old `lcd_lib.c` call signatures. |
| `main/main.c` -- `TouchCalibration()`, `ConvertCoordinate()` | `touch_calib.h` / `touch_calib.c`, `py/zeno_calibrate.py` | Two-point axis-separable scale+offset replaced with an affine least-squares fit (`zt_cal_solve()` in `zeno_pure.h`) over 3-9 points, so skew/rotation between the touch overlay and the LCD is correctable too (see `docs/CALIBRATION.md`). Calibration now persists to NVS (`zl_calib_save_nvs()`/`zl_calib_load_nvs()`); the original had no persistence (it's a one-shot demo). |
| `main/main.c` -- `app_main()`, `TFT()` task, hard-coded init/rotation | `modzlcd.c` (`lcd.init()`, `lcd.set_rotation()`), `modztouch.c` (`touch.init()`) | Bring-up is now called explicitly from Python instead of running automatically at boot, so Zeno OS's own boot sequence and other Python applications are untouched. |
| `main/Kconfig.projbuild` pin/geometry/touch symbols | `zeno_lcd_config.h` | Carried over verbatim as `#define`s; see `docs/GPIO_MAPPING.md`. |
| (none -- new) | `zeno_pure.h` | Every piece of logic that doesn't need a GPIO/ADC register (LUT construction, trimmed mean, axis-agreement check, debounce, affine solve/apply, rotation table) factored out so it can be unit-tested on a host compiler (`tests/host_test_pure.c`) without ESP-IDF or real hardware. |
| (none -- new) | `modzlcd.c`, `modztouch.c`, `micropython.cmake`, `zeno_mp_err.h` | MicroPython C-module bindings and `USER_C_MODULES` build glue; the original has no MicroPython integration at all (it's a standalone ESP-IDF app). |

Files from the original repo **not** ported (out of scope for this task,
or specific to the demo app rather than the driver):
`main/main.c`'s demo screens/animations, the other ~19 controller drivers
in `components/tft_library/` that `CONFIG_ILI9488`/`CONFIG_INTERFACE_REG`
don't select, and `main/Kconfig.projbuild` options for controllers/
interfaces other than the one this sdkconfig actually uses.
