# ESP32-S3 N16R8 Specific Notes

This document outlines considerations, missing features, and potential improvements for the ESP32-S3 variant with 16MB flash and 8MB RAM (PSRAM), often referred to as the N16R8 module.

## Hardware Specifics
- **ESP32-S3** chip with USB OTG support
- **16MB Flash** (for firmware and storage)
- **8MB PSRAM** (external RAM accessible via SPI)

## Current Configuration (ESP32_GENERIC_S3)
The default `ESP32_GENERIC_S3` board configuration in the port may not fully utilize the N16R8's capabilities. Check the following:

### Flash Size
- Ensure the flash size is set to 16MB in the ESP-IDF configuration (sdkconfig).
- Look for `CONFIG_ESP32_FLASH_SIZE` in the sdkconfig files.

### PSRAM Configuration
- The ESP32-S3 supports PSRAM. The port must be configured to use it.
- Check `CONFIG_SPIRAM` and related settings (size, speed, etc.).
- The heap initialization in `mpconfigport.h` may need adjustment for larger RAM.

### USB Support
- The ESP32-S3 has native USB. The port can enable:
  - USB Serial/JTAG console (`MICROPY_HW_ENABLE_USBDEV` and `MICROPY_HW_ESP_USB_SERIAL_JTAG`)
  - USB Device (CDC, MSC, HID) for peripheral mode
- Currently, the port may only use UART for REPL. Enabling USB can provide an alternative console.

## Potential Improvements

### 1. Increase Heap Size
With 8MB PSRAM, the MicroPython heap can be significantly larger than the default internal RAM heap.

**Where to change:**
- In `mpconfigport.h`, adjust `MICROPY_GC_INITIAL_HEAP_SIZE` to use external RAM.
- Note: The port already has logic for different chip types. You may need to add a condition for ESP32-S3 with PSRAM.

Example:
```c
#ifndef MICROPY_GC_INITIAL_HEAP_SIZE
#if CONFIG_IDF_TARGET_ESP32S3 && CONFIG_SPIRAM
#define MICROPY_GC_INITIAL_HEAP_SIZE    (1024 * 1024) // 1MB initial heap, can grow
#elif ... // existing conditions
#endif
#endif
```

### 2. Enable USB Console
To use USB for REPL instead of (or in addition to) UART:

**Steps:**
1. In `mpconfigport.h`, ensure:
   ```c
   #define MICROPY_HW_ENABLE_USBDEV        (1)
   #define MICROPY_HW_ESP_USB_SERIAL_JTAG  (1)
   ```
2. The USB Serial/JTAG will appear as a CDC ACM serial port on the host.
3. You may need to adjust the UART REPL settings if you want to disable UART REPL.

### 3. Utilize PSRAM for Specific Buffers
Certain buffers (like file I/O, networking) can be allocated from PSRAM to save internal RAM.

**How:**
- Use `MALLOC_CAP_SPIRAM` when allocating large buffers in C code.
- In MicroPython, you can use the `esp32` module's heap info to monitor usage.

### 4. Adjust Flash Partition Table
With 16MB flash, you can allocate more space for:
- OTA updates (two app partitions)
- Larger filesystem (if using internal filesystem)
- Custom NVS partitions

**Where to change:**
- Edit the partition table CSV file (usually in the board directory or generated by the build).
- Example: Increase the size of the `storage` partition or add a second OTA partition.

### 5. Enable Bluetooth and WiFi Coexistence
The ESP32-S3 supports Bluetooth LE and WiFi. Ensure both are enabled if needed:
- In `mpconfigport.h`: `MICROPY_PY_BLUETOOTH` and `MICROPY_PY_NETWORK_WLAN`
- In ESP-IDF configuration: Bluetooth and WiFi settings.

### 6. Optimize for Performance
- Set CPU frequency to 240MHz (if supported by the module) for maximum performance.
  - In `mpconfigport.h`: Adjust `MICROPY_PY_MACHINE_FREQ` or use `machine.freq()`.
- Enable compiler optimizations (already enabled by default in the port).

### 7. Use External RAM for Framebuffers
If using a display (e.g., LVIIPS), allocate the framebuffer in PSRAM to save internal RAM.

**How:**
- When initializing the display driver, use `malloc` with `MALLOC_CAP_SPIRAM` for the buffer.

## Missing Features (as of current port)
- **USB Host**: The ESP32-S3 can act as a USB host, but this requires additional software stack not included in the MicroPython port by default.
- **Ethernet**: While the ESP32-S3 has an Ethernet MAC, it requires an external PHY. The port does not include Ethernet support by default.
- **CAN**: The ESP32-S3 has a TWAI controller (CAN), but it is not exposed in the `machine` module.

## How to Test Changes
1. After modifying `mpconfigport.h` or board files, clean and rebuild:
   ```bash
   make clean
   make
   ```
2. Flash the firmware:
   ```bash
   make deploy
   ```
3. Check the heap size via REPL:
   ```python
   import gc
   gc.mem_free()  # Should show a larger number if using PSRAM
   ```
4. Verify USB console appears when connected via USB.
